# ADR-004: Блокировка прибора в Redis

## Контекст

На одном приборе одновременно может идти только одно измерение (FR-11), а воркеров несколько
(NFR-01). Воркер может упасть, не освободив блокировку, поэтому блокировка не должна жить вечно.
Сегмент измеряется секунды, развёртка целиком — минуты.

## Решение

- Ключ `lock:instrument:{id}` в Redis, реализация — `redis.lock.Lock` (атомарная установка со
  случайным токеном владельца, снятие и продление только владельцем).
- TTL 30 с (`MH_INSTRUMENT_LOCK_TTL_S`), продлевается после каждого сохранённого сегмента.
  TTL должен быть больше максимального времени одного сегмента.
- Блокировка берётся до перехода задания `queued → running`. Если прибор занят, движок
  выбрасывает `InstrumentBusyError`, Celery-задача делает `retry(countdown=5)`, задание остаётся
  в `queued`.
- Если при продлении выяснилось, что блокировка потеряна (истёк TTL, ключ удалён), измерение
  прекращается, задание получает `failed` с кодом `lock_lost`: прибор уже мог взять другой воркер.
- Переходы статуса задания — атомарные `UPDATE ... WHERE status = <ожидаемый>` с проверкой числа
  затронутых строк, поэтому дублирующая доставка задачи ничего не портит.

## Последствия

- Упавший воркер блокирует прибор не дольше TTL; задание при этом остаётся в `running`, пока его не
  вернёт сторожевой процесс (фаза 4).
- Redis становится единой точкой отказа для запуска измерений (API при недоступной очереди отдаёт
  503, а задание помечается `failed` с кодом `dispatch_failed`).
- Блокировка не защищает от прямого обращения к прибору в обход системы.
